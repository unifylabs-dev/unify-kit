# 0003 — Committed Workflow seeds follow the proven scriptPath body-execution contract (not a node-check-clean exported-entry module)

- **Status:** accepted
- **Date:** 2026-06-04
- **Decision:** A committed Workflow seed (e.g. `iterative-review.workflow.mjs`) is a single self-contained `.mjs` that: (a) begins with `export const meta = { name, description, phases }` as a **pure literal** (no variables, calls, spreads, template interpolation, or **string concatenation**); (b) inlines its tested kernel with all `import`/`export` stripped (the runtime VM cannot resolve modules); and (c) ends with a **top-level `return await main(args)` entrypoint**. The runtime executes the script **body** — there is **no** exported-entry auto-invocation — and the top-level `return` is the workflow's result; the `args` global arrives as a **JSON string** (the entrypoint parses it). Because a top-level `return` is not legal in a bare ES module, the committed bundle is **deliberately not validated by `node --check`**; a wrap-parse validator (`workflow/check-bundle.mjs`) validates it the way the runtime runs it. The agent API is `agent(promptString, { agentType, schema })`.
- **Context:** The first `iterative-review` bundle (M1 P3) was authored against an **assumed** Workflow API — object-form `agent({ agent, input })`, `meta = { name, version, entry, inputs }`, and an `export { main }` that the runtime was assumed to auto-invoke via `entry: 'main'`. During the M1 P6 live-gate attempt it was **empirically proven un-runnable** (probe `wf_5ce63311-1e4`): the object-form `agent` was coerced to a string and dispatched as a generic agent, the named reviewers never ran, and `main` was never called. A focused contract probe (`wf_5ffc08f3-c30`) then established the real shape above: the script body runs, a top-level `return` is captured as the result, `args` is a JSON string, and `agent(string, { agentType })` resolves the `pr-review-toolkit:*` types. A separate probe also showed `meta` must be a pure literal — a `+` concatenation is a `BinaryExpression` the tool rejects at submit time. CI runners have no `claude`, so they cannot run the Workflow tool to catch these — the contract must be enforced statically.
- **Consequences:**
  - `build-workflow.mjs` emits a top-level `return await main(typeof args !== "undefined" ? args : {})` entrypoint (not `export { main }`), and `glue.mjs`'s `meta` is a single-literal `{ name, description, phases }`. `main()` parses `args` defensively (string-or-object).
  - The committed bundle is **excluded** from the find-based `node --check` step; `node check-bundle.mjs <bundle>` validates it instead — wrap-parsing the post-`meta` body as an async function (the runtime shape) and asserting: zero imports, `export const meta` is the **sole** export, **meta is a pure literal** (statically rejects concatenation / template / spread / call — exactly what the runtime rejects at submit time), and a top-level `main()` entrypoint exists. The byte-for-byte parity guard, import-free grep, and tracked-file assertion are unchanged.
  - All `glue.mjs` reviewer/fixer/verifier calls use the real `agent(string, { agentType, schema })` API; placeholder agent types (`fixer` / `verifier-scout` / `verifier-runner`) that do not exist in the registry are replaced by the default workflow agent + a scout→`resolveVerifier`→runner verify path.
  - **This contract applies to every committed Workflow seed**, not just `iterative-review`. **Audited 2026-06-04: the `planning-brain` seed (`plugins/unifylabs-workflow/workflows/planning-brain/planning-brain.workflow.mjs`) carried the phantom shape** — `meta = { name, version, entry, inputs }` plus `export { main }` with no top-level invocation — so it would not run live as-is (its 26 tests covered the kernel + wiring + bundler determinism, not a live run — the same asserted-not-proven gap P3 had). **Adapted 2026-06-04** (M2) with the same engine↔runtime treatment + a live smoke run (`wf_3e271589-060`): pure-literal `{name,description,phases}` meta (the `+`-concatenated description was a rejected BinaryExpression), `main(rawArgs)` parsing the JSON-string `args`, the phantom `phase(name, fn)` callback wrapper removed (the real `phase(title)` returns void), a top-level `return await main(args)` entrypoint from the bundler, and a `check-bundle.mjs` validator + CI swap. Its `agent(string, {label, phase, schema})` calls were already the real signature (generic agents — no `agentType`). The seed now runs live.
  - A future change to the Workflow-runtime entry/return/`meta` contract requires re-proving via a fresh probe; the proven shape is recorded here and in the `iterative-review-engine-phantom-api` memory.
- **Alternatives considered:**
  - **Keep the node-check-clean module with `export { main }`** (P3's shape). Rejected — empirically proven it never runs (no exported-entry auto-invocation; the body, not an export, is executed).
  - **Top-level `await main(args)` with no `return`** (which *is* node-check-clean). Rejected — the workflow result is delivered only via the top-level `return`; the script runs in a sandboxed VM with no filesystem, so a run cannot surface its findings/report any other way.
  - **Run `iterative-review` as an inline `script` emitted by the skill at call time** (no committed bundle). Rejected — loses the reviewable, version-controlled, parity-guarded committed artifact the design (and the P6 live-gate protocol, which invokes the bundle by `scriptPath`) depends on.
  - **Keep `node --check` on the bundle.** Rejected — it raises "Illegal return statement" on the *correct* bundle; the wrap-parse validator checks the same syntax in the shape the runtime actually uses, plus the structural invariants `node --check` never could (imports, sole-export, meta-purity, entrypoint).
- **Supersedes / superseded by:** none.
