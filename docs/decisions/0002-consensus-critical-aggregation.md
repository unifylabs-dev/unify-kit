# 0002 — Multi-reviewer Critical findings aggregate by consensus (≥2 votes), not max-over-reviewers

- **Status:** accepted
- **Date:** 2026-06-04
- **Decision:** In the enforced `iterative-review` loop, when N independent reviewers fan out over a change, a finding is aggregated as **Critical** only if **≥2 distinct reviewers** independently tier a Critical within **±3 source lines** of it (same file); otherwise it is **demoted to Important**. Findings are then de-duplicated by the canonical key `(file, line, severity, normalized-description)`. This replaces the original `references/severity-policy.md §"Aggregation across multiple agents"` rule ("group by file:line, **pick the highest severity**"). Encoded in the pure, unit-tested kernel module `plugins/unifylabs-workflow/skills/iterative-review/workflow/lib/consensus-aggregate.mjs`.
- **Context:** The M1→M2 no-regression trust gate (design §12, §14 #3) requires the enforced loop's verification quality to be **≥ the human-gated baseline**, including **worst-of-N critical false-positives ≤ baseline (0)**. A faithful pre-build de-risk — N=3 runs × the 6 `pr-review-toolkit:*` reviewers over the frozen code-mode benchmark, scored by the landed `run-no-regression-eval.mjs` — proved that **max-over-reviewers aggregation is precision-fragile**: in one run a single reviewer (silent-failure-hunter) stochastically scored a gold-**Important** missing-`await` at exactly 90 → Critical, which under "pick the highest severity" became the run's verdict → worst-of-N FP = 1 → gate **FAIL**. The human baseline scored FP=0 precisely because it was **one calibrated judgment**, not a max over six independent callers. The two real, unanimous Criticals (caught by every reviewer) were never at risk; only the lone over-escalation was. A later live worst-of-3 also caught a *second* instance of the same class (container-path Criticals reaching consensus — fixed separately by pinning the citation convention), underscoring that the union step, not the reviewers, was the precision hazard.
- **Consequences:**
  - New pure kernel module `lib/consensus-aggregate.mjs` (deterministic — no wall-clock/random/agent variance — and `node:test`-covered, 10 cases incl. a gate-the-gate regression mirroring the captured de-risk). It runs in the glue's review callbacks (`initialReview` / `reviewRound`) **before** the stopping engine sees any findings, so the engine's tier bookkeeping and the report agree on what is Critical.
  - `references/severity-policy.md §Aggregation` rewritten (max → consensus); `§Severity overrides` now states an explicit `severity: critical` tag counts as **that reviewer's vote**, and consensus decides the aggregated tier.
  - **Validated before the build:** applying the rule to the captured live transcripts and re-scoring with the *unmodified* scorer flipped the verdict FAIL→PASS (worst recall 2/3, worst FP 0). The post-build N=3 live gate then passed worst-of-3 on the committed bundle.
  - **Trade-off:** a genuine Critical that only 1-of-N reviewers catches is demoted to Important — it still surfaces (auto-fixed by default, or collected under `--gate-important`) but does not auto-block the run. This is acceptable because the loop deliberately fans out multiple reviewers and a lone-reviewer Critical is exactly the over-escalation class the gate must reject. A future refinement may let `security`-category Criticals bypass consensus; M1 does not, to keep the gate's aggregation deterministic.
- **Alternatives considered:**
  - **Max-over-reviewers** (the original `severity-policy.md` rule). Rejected — empirically falsified by the de-risk: precision-fragile, produces an intermittent worst-of-N FP under any single reviewer's stochastic over-escalation.
  - **Adversarial Critical-verify** — spawn an independent skeptic to re-judge each Critical, demote if unconfirmed. Robust (reasons per-finding, handles the lone-sharp-reviewer case), but adds agent calls **and agent-side variance into the gate itself** and costs more per loop round. Rejected for M1; a candidate for a future quality tier.
  - **Single calibration agent** — one agent re-tiers all union Criticals in a holistic pass (mirrors how the human baseline got FP=0). Cheaper than per-finding verify, but reintroduces a single point of judgment + that agent's variance. Rejected for M1 in favor of the deterministic, kernel-testable consensus rule.
- **Supersedes / superseded by:** none. Refines `references/severity-policy.md §"Aggregation across multiple agents"`.
