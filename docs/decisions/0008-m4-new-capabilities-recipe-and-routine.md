# 0008 — M4 new capabilities: a read-only `/workflow-library` reference recipe (seed+docs, NOT a command) + a detect-only `doc-freshness` routine pilot; cloud `RemoteTrigger` 401 → registration is a consumer step; recipe-local consensus (no copied lib) + the FP-heavy citation signal moved to the routine's LLM layer

- **Status:** accepted
- **Date:** 2026-06-08
- **Decision:** M4 (new capabilities) ships **exactly two additive, revert-clean artifacts**, both proven to RUN LIVE: **(A) the `review-changed-files` reference recipe** — the first entry in a new `/workflow-library`, shipped as a **curated docs catalog (`docs/workflow-library.md`) + an ADR-0003 committed seed** at `plugins/unifylabs-workflow/workflows/recipes/review-changed-files/` (a read-only `parallel()` fan-out of N dimension reviewers over a git diff → Critical-precision consensus → adversarial verify), **NOT a first-class slash command** (D1); and **(B) the `doc-freshness` detect-only routine pilot** — a repo-intrinsic, `$HOME`-free, read-only detector (`scripts/doc-freshness-scan.sh`) + a `/schedule`-able routine recipe (`plugins/unifylabs-workflow/workflows/routines/doc-freshness/`) that runs the detector + adds LLM judgment and reports via a single idempotent `gh issue` find-or-update, **never mutating the repo** (D2 = doc-freshness alone; D5 = ship the routine). Both deliverables are **seed/docs/script shape → NO count ripple, NO version bump** (plugin stays v2.1.0; 13 skills / 17 commands / 9 hooks unchanged); the only CI change is **one new `review-recipe-harness` job → 20→21 jobs**. The five design decisions are dispositioned: **D1** seed+docs (Tomer delegated the call; the name implies a command, but the "recipe runs" exit bar needs no verb surface, and a command would re-introduce the ~15-location Theme-9 count-drift class M0 just eliminated — and it is a reversible, promote-later-if-the-library-grows call); **D2** doc-freshness alone (cloud-ready today; `check-drift.sh` is verified entirely machine-local — its clone-sync + `~/.claude` symlink checks are meaningless in a cloud routine — so a drift-check routine needs a from-scratch repo-intrinsic variant, deferred to BACKLOG); **D3** never-mutate is scoped to the **repo tree**, and the single `gh issue` find-or-update is the one allowed GitHub-state write; **D4** the recipe ships a full tested seed with a new CI harness, but with **recipe-local consensus arithmetic (NOT a copied `consensus-aggregate.mjs`)** — so the harness drops the copied-lib `cmp` byte-identity guard and a self-contained recipe stays copy-pasteable; **D5** ship the cloud routine (it showcases the routines tier M4 exists to pilot), justified by the genuinely **judgment-bearing** signals (citation-drift, architecture-lag) the deterministic script cannot do precisely, with the honest caveat that the mechanical signals alone could run as a cheaper cron Action.
- **Context:** M4 is "new capabilities" (design §8 / §12 / §14 #4): one reference `/workflow-library` recipe + one detect-only routine pilot. The work was dogfooded `/phasing-flow plan`-style: a 6-reader **Understand** workflow (`wf_1e915575-cfe`) produced a file:line-anchored facts brief; the live **planning-brain** seed (`wf_94ffb280-d70`, `ground:false`) synthesized the master plan, whose **adversarial critic** re-verified six load-bearing claims against live code and made four corrections that OVERRODE the facts brief — most importantly killing a proposed "security-hook backstop" never-mutate layer (verified: `dangerous-actions-blocker.sh` blocks only `rm -rf`/`DROP`/`dd`/`mkfs`; `file-guard.sh` only credential files; **no kit hook blocks `git commit`/`push`**, and a cloud routine loads none of this repo's hooks anyway) and the "git status clean" never-mutate proof (a category error — the routine runs against its own cloud checkout). Per **gate-on-decisions**, the genuine design choices (D1, D5, the probe fallback) were surfaced to a human GATE; D2/D3/D4 were judge/executor-settled. A **front-loaded PROBE** then resolved the routine primitive empirically before any routine design (the front-loaded-probe principle): the loaded canonical tool is **`RemoteTrigger`** (`/v1/code/triggers`; the on-disk `schedule` skill's `create_scheduled_task` is its UX wrapper; `CronCreate` is session-local and unfit for a maintenance tier), but **read-only `RemoteTrigger list` returned HTTP 401 `authentication_error` twice** — claude.ai is unauthenticated in this build env (as the env note warned for headless runs). This is **PROBE branch P-c**.
- **Consequences:**
  - **New artifacts (additive):** `plugins/unifylabs-workflow/workflows/recipes/review-changed-files/` (the ADR-0003 RIG: `lib/consensus.mjs` pure kernel + `src/glue.mjs` + `build-workflow.mjs` + `check-bundle.mjs` + the committed `review-changed-files.workflow.mjs` bundle + `test/consensus.test.mjs` [16 cases] + `README.md`); `plugins/unifylabs-workflow/workflows/routines/doc-freshness/` (`routine-prompt.md` + `README.md`); `scripts/doc-freshness-scan.sh` (shellcheck-gated by the existing `scripts/*.sh` lint glob — the maintenance-script precedent, like `check-drift.sh`); `docs/workflow-library.md` (the catalog = the `/workflow-library` surface); this ADR + its index row.
  - **CI:** one new `review-recipe-harness` job in `plugin-install-fixture.yml` (node --check, node --test, bundle parity = regenerate + `git diff` + `check-bundle` + import-free, and a RED self-test that sabotages the consensus rule `>= critVotes → >= 0` and asserts the suite fails). **No copied-lib `cmp` guard** (the recipe owns its consensus — D4). **20 → 21 jobs.** No new `changelog-check`/`scrub-check`/shellcheck/markdownlint glob is needed (the recipe lives under `plugins/`, the script under `scripts/`, the catalog under `docs/` — all already covered).
  - **Live evidence (both deliverables RUN LIVE):** recipe run **`wf_3c45b7ca-f8c`** — 8 agents (3 reviewers → consensus → 5 critical verifiers) over a staged planted-bug target → **11 findings, 5 Criticals confirmed** (e.g. RCE via `eval`, an unguarded `JSON.parse`, a null-deref, a hardcoded `sk-live-` secret), each adversarially verified `refuted:false`; the `eval` line reached Critical only via two-dimension consensus; zero working-tree mutation. Detect script: **baseline `✓ FRESH` (exit 0, zero false positives)** on the current tree, and a **true-positive** (a stub 14th skill staged without a count ripple) fired exactly 3 correct signals (count drift in `CLAUDE.md` + `README.md`, skill-without-doc-entry) → exit 1, then reverted clean. The `lib/consensus.mjs` kernel's own tests caught two real bugs during the build (`Number(null) === 0` let an unlocatable line vote and dedup as line 0) — fixed via a `toFiniteLine` guard, not by weakening the tests.
  - **P-c consequence — the routine's cloud registration is a CONSUMER step.** The kit cannot register a per-repo cloud routine from an unauthenticated build env, and a cloud run id was NOT fabricated. The exit proof "routine reports (never mutates)" is met by the **detect script running live locally** (its detection + read-only posture are the substance); `routines/doc-freshness/README.md` documents `RemoteTrigger`/`schedule` registration for a consumer's authenticated env. The cloud routine, once registered, survives a `git revert`, so the **revert ledger includes `RemoteTrigger delete <id>`** in addition to deleting the dirs/script/catalog/ADR + restoring the count narrative.
  - **Never-mutate (stated honestly, P-b/P-c):** the guarantee rests on (1) the detect script being **provably read-only** (only `grep`/`find`/`test`/`git log` + print — no write path; stronger than a prompt), (2) prompt posture, and (3) the single `gh issue` emit being GitHub state, not a repo-tree write (origin-log-inspectable). An **API-level read-only tool-allowlist was NOT verifiable** (never reached a 200), so the ADR records that layer as consumer-configurable-and-unverified-here — it does NOT claim a security-hook backstop.
  - **The FP-heavy citation signal moved to judgment.** A deterministic bash existence-check on doc→path citations produced **32 false positives** on the clean tree (plugin-relative shorthand, aspirational template paths, historical `docs/audit/*` references). That signal was removed from the deterministic script and assigned to the routine's LLM layer (`routine-prompt.md`) — which is precisely the agentic value a cloud routine adds over a cron Action (D5).
- **Alternatives considered:**
  - **Ship `/workflow-library` as a first-class slash command (D1).** Rejected — triggers the full Theme-9 count chain (~15 files) + a minor version bump + new CI assertions for a discoverability gain the catalog already gives; the "recipe runs" exit bar needs no verb surface; reversible to a command later if the library grows.
  - **Ship BOTH routines (drift-check + doc-freshness) (D2).** Rejected for the pilot — `check-drift.sh` is verified entirely machine-local (clone-sync + `~/.claude` symlinks), so a drift-check routine is from-scratch repo-intrinsic work; doc-freshness is cloud-ready today and its count-drift signal already covers the M0 pain. Drift-check's repo-only variant deferred to BACKLOG.
  - **Copy `consensus-aggregate.mjs` into the recipe (D4 default).** Rejected — a fourth copy of the locked lib forces a `cmp` byte-identity CI guard AND makes the reference recipe non-copy-pasteable (a user would need the copied lib too). A recipe-local, tested consensus kernel is self-contained and drops the guard.
  - **Keep the deterministic dangling-citation signal in the script.** Rejected — 32 false positives on a clean tree; the distinction (real drift vs shorthand/aspirational/historical) is irreducibly a judgment call.
  - **Block M4's routine until claude.ai auth is available (the exit-proof gate).** Rejected at the G1 gate — Tomer pre-decided the P-c fallback: land the recipe + the detect-script-live proof + the routine recipe, document cloud registration as a consumer step; never fabricate a cloud run id.
  - **A `schedule:`-cron GitHub Action instead of a cloud routine (D5).** Rejected — it is an existing capability, not the routines tier M4 pilots; the routine earns its place on the judgment-bearing signals + the human-channel report, with the honest caveat recorded.
- **Supersedes / superseded by:** none. Builds on **ADR 0003** (the committed-seed scriptPath contract the recipe and the routine recipe both follow), **ADR 0002** (the consensus ≥2 rule the recipe re-expresses recipe-locally), and **ADR 0005/0006** (the M3 seed + à-la-carte-by-primitive adoption precedent). Implements the design's Theme-7 (new capabilities) and §14 #4 (routines scope).
