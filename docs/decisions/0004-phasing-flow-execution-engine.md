# 0004 — The phasing-flow execution-engine seed: frozen-vocabulary reuse, copied-lib byte-identity, deterministic-first verification, and no fixed-point ceiling in M2

- **Status:** accepted
- **Date:** 2026-06-05
- **Decision:** The phasing-flow execution engine (M2 deliverable D1) is the **third committed Workflow seed** under the ADR 0003 scriptPath contract, after `iterative-review` and `planning-brain`. Four sub-decisions: **(a)** it REUSES the frozen 7 exit-reason vocabulary (`lib/exit-reasons.mjs`) by **generalizing `criticals-pending-gate`** to "any residual blocking finding" (a RED deterministic verify OR a consensus-Critical diff finding) — **no new member is added**; **(b)** its **7 generic `lib/` modules are COPIED VERBATIM** from `iterative-review` and held byte-identical by a CI diff-guard (single source of truth, NOT a cross-seed bundle import); **(c)** verification is **deterministic-first** — the in-run project verifier is authoritative and fails **CLOSED** (a throw, a permanent failure, or an unrecognized verdict routes to `aborted`, never silently passing a unit), while the adversarial consensus-≥2 diff-reviewer can only **RAISE** a gate and fails **OPEN** (a throw or non-finite return is coerced to 0, never blocks); **(d)** M2 does **NOT** wire a `fixed-point` stall ceiling — with a strictly-advancing serial cursor a stall cannot occur, so the loop is bounded by the unit count + the `cap` ceiling, and a stall guard is deferred to M3 (parallel fan-out / retries, where the cursor can genuinely stall).
- **Context:** M2's flagship engine generalizes the `iterative-review` enforced loop-until-dry to a serial loop over an approved `units[]` plan: per unit, `executeUnit → deterministic verify → adversarial diff-review`, exiting on a provable ceiling. An **adversarial kernel review** (Workflow run `wf_0cf2db43`, 5 reviewers, before the bundle was committed) found three load-bearing problems with the first cut. **(1)** A Set-based `fixed-point` ceiling over `(id, title)` unit keys is **structurally unreachable** on valid serial input (a clean advance always shrinks the remaining set by exactly one) AND a **false-positive landmine**: two legitimately distinct units that share a label (e.g. two phases both titled "Wire up the route") collapse in the Set, so completing the first leaves the set unchanged → a false `fixed-point` exit that silently drops real work. Shipping a ceiling that cannot fire on valid input and misfires on plausible input contradicts the "ceilings are PROVABLE by running code" ethos the M1 trust gate established. **(2)** The relative circuit-breaker captured its baseline from the pre-loop spend, which is commonly 0, so `5 × 0 = 0` tripped the breaker on any spend (a healthy run false-aborted after one unit). **(3)** The fail-open diff-reviewer only honored a non-finite *return*; a reviewer that *threw* (the common agent death-mode) propagated out and crashed the run with no frozen report — silently *blocking* instead of failing open.
- **Consequences:**
  - The engine kernel is `execution-engine.mjs` (the serial loop over injected `executeUnit`/`verify`/`diffReview` callbacks + the copied ceilings) + `verify-verdict.mjs` (per-unit signals → a frozen exit reason via `assertExitReason`) + `wrapper.mjs` (→ a frozen units-domain report). `src/glue.mjs` is the only runtime-touching file. 35 zero-dep `node:test` cases, red-capable. The bundle **runs live** — smoke `wf_ddbd2cbb-581` (clean, 1/1) and `wf_2cc8aa35-512` (a RED `make test` → `criticals-pending-gate`).
  - The relative breaker now captures its baseline **after the first unit's clean cycle** (the cost of doing one unit) and is armed only from the second unit on; a single-unit run is never gated. `executeUnit`/`verify`/`diffReview` rejections are caught and routed (execute throw → `aborted`; verify throw → `aborted`; diffReview throw → fail-open 0), each logged to `truncationLog`.
  - The copied `lib/` set is **7** (`exit-reasons`, `clamp`, `canonical`, `make-return`, `budget-guard`, `verifier-detect`, `consensus-aggregate`) — `verifier-detect` (the glue's verify path) takes the slot ADR-era planning earmarked for `fixed-point`. A new `phasing-flow-engine-harness` CI job runs `node --test`, the bundle parity guard, `check-bundle`, the import-free assertion, the **copied-lib byte-identity diff-guard vs the iterative-review originals**, and a RED self-test.
  - `unit-cursor.mjs` + `fixed-point.mjs` are absent from M2 (the cursor is a plain integer index). M3 reintroduces a stall guard when parallel/retry makes the cursor able to stall.
- **Alternatives considered:**
  - **Keep the `fixed-point` ceiling wired** (the approved master-plan's R4). Rejected — the adversarial review proved it is dead on valid input and a false-positive landmine on duplicate-labeled units; a provable ceiling that cannot be behaviorally exercised is against the ethos.
  - **Cross-seed import of the shared `lib/` from the `iterative-review` path** (one angled plan proposed it). Rejected — it breaks the self-contained-seed invariant (ADR 0003), makes the bundle non-regenerable if the other seed moves, and is not live-proven. Single-source-of-truth is achieved by a copy + a CI byte-identity diff-guard instead.
  - **Add a new exit-reason member for a unit-level block.** Rejected — `criticals-pending-gate` already documents "any residual blocking finding"; the vocabulary stays frozen at 7. A genuinely-new semantic would be an ADR escalation, not a silent set edit.
  - **Fail the diff-reviewer CLOSED** (a dead reviewer blocks). Rejected — the deterministic verify is the authoritative gate (the adversarial layer is defense-in-depth); a flaky LLM reviewer must never block a unit its deterministic verifier passed.
- **Supersedes / superseded by:** none. Builds on **ADR 0003** (the committed-seed scriptPath contract — this is its third instance) and **ADR 0002** (consensus ≥2 aggregation — reused verbatim for the adversarial diff-reviewer).
