# 0007 — spec-it stays unwired: the planning-brain wire DECLINED by a pre-registered blind probe (2/5 dims, redundant with Phase-7 iterative-review); the matrix:67 engine→planning-brain divergence ratified; floor stale-ref fixes only

- **Status:** accepted
- **Date:** 2026-06-08
- **Decision:** M3 adoption **skill 3 of 3 (the last)** evaluated wiring `spec-it` onto the phasing-flow framework and **DECLINED the wire on empirical evidence** — spec-it keeps its existing 11-phase in-session flow byte-for-behavior unchanged. Three sub-decisions, resolved at the GATE-2 plan gate + a final evidence micro-gate (planning-brain run `wf_be35d256-652`, whose adversarial critic elevated NO-OP from "first-class but unlikely" to **the leading hypothesis to falsify**): **(a) OD-3 RATIFIED — impact-matrix:67's "adopt engine + /goal" is read for spec-it as "adopt the planning-brain, NOT the execution engine"** — spec-it is *planning-shaped* (deliverable = a prose spec + a `gh issue create` filing; no per-AC code diff, no resolvable verifier), so the fail-CLOSED engine would `resolveVerifier → []` and silent-pass on spec-it's own deliverable, and `/goal verify` is a no-op for a doc; **(b) OD-1 = NO-OP (the wire DECLINED)** — per gate-on-decisions, OD-1 was NOT pre-decided; a **pre-registered, blind, 3-grader probe** drove the live planning-brain seed AS-IS on its *strongest* framing (Phase-4 decomposition — the only native `steps[]` fit) against spec-it's current single-pass in-session flow, on a real spec idea (magic-link auth), and the seed scored **2 of 5** decomposition dimensions, below the **≥3-of-5** bar written *before* the run; **(c) OD-2 = moot under NO-OP** — default-ON-no-flag was the judge-settled choice *if* a wire had landed (a `--deep-plan` toggle would re-introduce the opt-in escalation layer ADR 0006 §i deleted; spec-it has no S/M/L axis to condition on); recorded, not applied. The only edits that ship are the **floor stale-ref fixes** (the impact-matrix:67 "update phasing refs" clause) — three sites across two files: the stale `/work-issue` **Phase-3.5** reference at `spec-it/SKILL.md:233` (Phase 3.5 was deleted by ADR 0006 §f) is corrected, the softer phasing ref at `:523` is reconciled, and a third stale Phase-3.5 ref in `references/decomposition-heuristics.md:4` is corrected. **No pointer block, no `Workflow` in `allowed-tools`, no frozen-region guard, no 21st CI job — CI stays 20/20; the `/spec-it` consumer contract is byte-for-behavior unchanged.**
- **Context:** M3 wires `work-issue` / `spec-it` / `integrate-branch` onto the framework à-la-carte by primitive; spec-it is third and last — the lowest engine-coupling case (planning-shaped, no execution engine). The plan-of-record *assumed* spec-it would adopt the planning-brain for its research/decompose front half. The work was dogfooded `/phasing-flow plan`-style: a 5-reader **Understand** workflow (`wf_fa3a1ca1-eee`) produced a file:line-anchored facts brief; the live **planning-brain** (`wf_be35d256-652`) synthesized the master plan whose **adversarial critic** made the central correction — all three angled planners had *soft-converged* on "Phase-4 advisory" while each claimed independence, and the evidence pointed harder at NO-OP: the seed's lenses (`minimal_scope`/`robust_general`/`risk_provability`) are wrong for spec drafting AND for decomposition (which wants partition lenses); `steps[]` is execution-plan-shaped while all three spec-it artifacts (unordered impact map, child-issue graph, completeness-driven spec sections) are not ordered work; **Phase 7 already runs `iterative-review` adversarially over the draft**; the 1M window neutralizes the context-relief motive at spec-sized scope (the same logic ADR 0006 used to S-scope-SKIP work-issue's seed and delete `--phase`); and an "advisory" Phase-4 output is proposed child-issue titles a human re-decides at Gate 4 anyway — a sub-agent round-trip for output the human overrides. So OD-1 was sent to a **front-loaded, pre-registered, blind probe** (the M3 discipline: live-prove the load-bearing assumption *before* the build), with NO-OP as the leading hypothesis and the pass/fail bar fixed in writing first to forbid post-hoc rationalization.

  - **Live evidence (the probe, this session):** ARM-SEED `wf_75ec458e-5b9` (planning-brain at Phase-4 decomposition, `ground:false`, **non-null `master_plan` → null-rate 0**; 2/2 with the plan run `wf_be35d256-652`); the **blind grading** `wf_f8ad756d-9d8` (3 graders, seed/baseline→X/Y varied per grader, scored against the pre-registered `PROBE-RUBRIC.md`): the seed won **completeness 3-0** + **actionability 3-0** but LOST **partition 1-2** + **dependencies 1-2**, with granularity a tie → **2/5 < the ≥3 bar → NO-OP**. The decisive, **probe-independent** finding: the single-pass baseline beat the seed on the two **structural** dimensions — **partition + dependencies** — that are Phase-4 decomposition's actual, unique job, exactly as the **shape-mismatch** predicts (`steps[]` is ordered-work-shaped; a decomposition is an unordered partition + dependency graph). The seed's two wins were completeness + AC-rigor: the **AC-rigor** win is largely recovered downstream (those sharper ACs land in the draft that Phase-7 `iterative-review` already reviews), while the **completeness** win (missing security *children* surfaced at the partition) is a **residual gap we accept** — NOT on a claim that Phase-7 provably re-derives it, but because the seed was *simultaneously worse* at decomposition's core structural job, so the wire is not a free win. All 3 graders preferred the seed **holistically**; we honor the pre-registered per-dimension bar (locked before any run, with a pro-seed borderline clause it never needed) over the holistic preference — and the seed **LOST**, did not merely tie, the two structural dimensions, so this is not a borderline 3/5 rationalized down. The probe is **N=1** (one subject — magic-link auth, a security-heavy feature — one run per arm); we generalize because the measured structural loss converges with the probe-independent shape-mismatch argument, and judged a second ~1.5M-token subject not worth it given that convergence (a different subject is the natural next step if spec-it decomposition quality later proves a real pain point). Evidence files: `.phasing-flow/m3-spec-it-ground/{PROBE-RUBRIC.md, PROBE-RESULT.md}`.
  - **M3 (adoption) is COMPLETE** — all three skills resolved: integrate-branch (ADR 0005, wired) + work-issue (ADR 0006, wired) + spec-it (**this ADR, evaluated-and-declined**). A dogfood loop that can honestly conclude "do not wire" is the native-first-but-quality-first principle ("keep the existing tool if it is already best") working as designed.

  - **Take impact-matrix:67's "adopt engine" literally.** Rejected as a technical fact — the execution engine fail-CLOSED-aborts on spec-it's prose/`gh`-filing deliverable (no resolvable verifier); the line is ratified as "adopt planning-brain" — which the probe then *also* declined.
